## 开摊：常驻运行

确认 `config/config.yaml` 里是 `start_mode: fused`（没有外参时用 `follow`），然后：

```bash
scripts/production.sh start
```

它把控制台作为 systemd 用户服务运行：脱离终端，异常退出会自动拉起并回到 `start_mode` 指定的模式。异常重启时舵机力矩不会掉，手臂停在原位，新进程接管后回初始位继续。

```bash
scripts/production.sh status     # 看状态
scripts/production.sh logs       # 跟着看日志
```

<Notice kind="caution">
服务运行的是仓库目录里当前检出的代码，应检出 `main`。运行期间不要在这个目录里切分支或改代码；要开发就另开一个 git worktree，并用别的端口。
</Notice>

## 来人了：恢复全量展示

```bash
scripts/lab.sh restore
```

也可以点网页顶部的“恢复全量展示”。它让借用机械臂的试验程序退出，把臂接管回来，几秒完成。没有借出任何臂时它什么也不做，随时可以放心执行。

## 没人时：借一只臂做试验

```bash
scripts/lab.sh lend right
```

<LendRestore />

它先等所有在展示的臂连续 8 秒没在跟手，再让生产停止指挥右臂并松开串口；舵机力矩不变，臂停在原位，左臂照常展示。网页顶部会出现黄色提示条，写明哪只臂没有参与展示。120 秒内一直有人在互动就放弃。

改好的代码想上线：合并到 `main` 后执行 `scripts/lab.sh deploy`，它在没人互动时跑一遍测试并重启服务。

## 人要离开：看门狗

```bash
uv run soarm-tools watchdog
```

它是独立进程，只读地盯着控制台的状态。出现下面任一情况，就让两只臂**收到休息位、释放力矩，然后急停**：

| 情况 | 判定 |
|---|---|
| 实际位置与指令偏差过大 | 超过 30° 并持续 1.5 秒 |
| 反复受阻 | 60 秒内出现 3 次“受到阻挡” |
| 关节超出限位 | 超出 6° 并持续 1 秒 |
| 夹爪低于基座平面 | 持续 1 秒 |
| 某只臂与控制台断开 | 持续 3 秒 |
| 控制环变慢 | 低于 15 Hz 并持续 3 秒 |
| 控制台没有响应 | 连续 6 秒读不到状态 |
| 控制台异常重启过 | systemd 的重启计数增加 |

它看不到舵机温度、电压，也看不到画面内容，不能替代现场有人。急停之后要人到场确认，并在网页上解除。

<Notice kind="info">
重启生产之前先停掉看门狗，重启完再开。否则它会把重启当成异常。
</Notice>

## 收摊

```bash
scripts/production.sh stop
```

两只臂先收到休息位，再释放力矩。等手臂完全停稳后再断电。断电后云台会垂下来，这是正常的，下次开摊用 `head-set` 转回去。
