# 文档站点的结构与设计约定

## 为什么是一条线路

上手是一段有先后的路：装环境、接线、配置、启动、值守。大多数人手上是现成的套机，一路走到底；少数人拿到新套机，要多做两件事再回到主路上。这正好是一张线路图：主线、一条离开又回来的支线、一条随时可查的速查线。

所以导航是一张线路图，而不是目录树。读者任何时候都能看到自己在哪一站、还有几站、支线从哪换乘。

## 数据流

```text
src/data/route.ts ──► Rail.astro        线路图（位置由站点顺序算出，线只在 45° 和 90° 转弯）
                 ├──► Doc.astro         当前站、第几站、上一站 / 下一站
                 └──► RouteTable.astro  首页的线路表
src/pages/*.mdx  ──► Doc.astro          正文；二级标题编号成步骤
```

线路只定义在 `route.ts` 一处。页面文件只管自己的内容，不知道前后是谁。

构建结果是纯静态文件。页面上只有一小段内联脚本：小屏幕上展开线路图、给代码块加复制按钮、给表格加横向滚动、量出步骤线的起点。脚本不运行时内容照样完整可读。

## 设计约定

- **色板**（`global.css` 顶部的变量）：珐琅深蓝的线路牌，瓷白的阅读栏，四条线的颜色——朱红主线、琥珀支线、钴蓝速查线，绿色保留给以后的现场线。线的颜色只用于线、站点和少量强调；正文文字用它们的深色版本以保证对比度。
- **页面跟着所在的线变色**：`<html data-line>` 决定 `--line`，步骤圆环、步骤线、页尾的粗线都用它。
- **正文安静**：阅读栏最宽 44rem，正文 17px。线路的视觉语言只出现在线路牌、步骤编号和页尾，不进入正文。
- **状态是记号不是颜色**：已在真机验证是实心圆，尚未验证是空心环（`Mark.astro`）；“尚未验证”的通告用虚线而不是色块。
- **通告**分四种，标签是一整条色带加图标，不用左侧色条。
- **动效只有一处**：换页时亮着的站点标记沿线路移到下一站（跨文档的 view transition）。系统设置了“减少动态效果”时不播放。
- **字体自托管**（`@fontsource-variable/*`）：中文用 Noto Sans SC，西文和数字用 Overpass，代码用 JetBrains Mono。中文字体按字符范围切片，浏览器只下载用到的部分。不依赖任何外部字体服务。
- **小屏幕**：线路牌收成顶部一条，按钮显示当前站名，点开是完整线路图。步骤编号改为行内数字。

## 内容约定

- 每个会让硬件动的步骤前有“机械臂会动”的通告，说明它会怎么动。
- 每一步写清“应该看到什么”，以及不对时去哪。
- 命令必须与仓库里的实际命令一致；改了命令行工具要同步改这里。
