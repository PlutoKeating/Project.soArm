# 架构

## 总览

```text
浏览器 (frontend/)
   │  REST 命令 / WebSocket 状态与按键 / MJPEG 视频
   ▼
Web 服务 (app.py, FastAPI)
   │
   ▼
控制器 (control/controller.py)  30 Hz 循环 ──────────► 机械臂 / 云台 (robot/)
   ▲                                                    真机: LeRobot Feetech 总线
   │ 主手位置（腕部: 画面坐标；头部: 3D 坐标）              模拟: MockArm / MockHead
相机线程 (perception/cameras.py)  每路相机一个
   └─ 手部检测 (perception/hand.py, MediaPipe)
```

一个进程，四类线程：Web 服务的事件循环、一个控制线程、每路相机一个采集线程和一个检测线程。采集线程持续取帧、只留最新一帧，检测线程总是处理最新的那一帧；控制线程只读检测线程给出的“主手”结果，不等待图像。任何一环慢了都只是跳过旧帧，延迟不会累积。

## 模块边界

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `robot/` | 读关节角、写目标角、开关力矩 | 不含任何控制逻辑 |
| `kinematics.py` | URDF 正解；位置 + 俯仰的 4 自由度逆解 | 不知道安全限制 |
| `perception/` | 取帧、检测手、锁定主手、深度反投影、画标注 | 不控制机械臂 |
| `control/controller.py` | 模式状态机、三种模式的目标计算、全部安全处理 | 不直接碰串口和相机设备 |
| `calib.py` | 触点法外参求解与存取 | |
| `app.py` | 把控制器暴露成 HTTP / WebSocket，提供前端静态文件 | 不含控制逻辑 |
| `tools.py` | 上电准备：扫描舵机、找相机、核对或重做校准 | |

## 关键设计决定

**底层用 LeRobot 的电机总线，校准直接读舵机。** 串口通信用 LeRobot 0.7.0 的 Feetech 总线。校准不走校准文件，而是读舵机里已保存的零点偏置和行程限位，读写都用原始刻度，也不改写舵机里的校准。连接流程自己写，是为了保证顺序：关力矩 → 写运行参数 → 目标对齐到当前位置 → 上力矩，连接瞬间手臂不跳。

**逆解自己实现，不用 LeRobot 的 placo 求解器。** SO-101 只有 5 个臂关节，做不了任意 6 维位姿。这里解的是与机构匹配的 4 维任务（夹爪参考点位置 + 夹爪俯仰角），用阻尼最小二乘迭代，wrist_roll 由上层直接给定。每一步都检查残差，残差大就拒绝这一步，目标不会跑出可达范围。

**角度约定。** 关节角用度，以刻度 2047 为零度，假定与 `so101_new_calib.urdf` 同零位同方向。LeRobot 校准时把手臂摆在中间姿态并把该处设为 2047，这个姿态就是 URDF 的零位。没有采用 LeRobot 自带的“行程中点为零”的换算：实测这套设备上次校准时有的关节没走满行程，行程中点与真实零位能差到 20° 左右。基座系：x 向前，y 向左，z 向上；肩部旋转的正方向是向右转。

**每只臂有自己的关节限位。** 生效的限位是三者的交集：URDF 限位、这只臂舵机里记录的行程限位、配置里的额外限位（`arms.<名字>.joint_limits`）。舵机会在固件层面拒绝超出行程限位的目标，所以控制层必须知道它，否则目标与实际会分叉并触发受阻让位。额外限位用于避让两臂之间的相机中柱：左臂肩部旋转不超过向右 30°，右臂不超过向左 30°。逆解、限位裁剪、回位目标和腕部跟随的偏转量都按这个交集收紧。

**初始位与休息位。** 初始位在配置的 `home` 里，每只臂可以用 `arms.<名字>.home` 覆盖个别关节。腕部旋转取 −90°，实测这样腕部相机画面才是正的。休息位不写死：首次连接时手臂是无力停放的，那个姿态就记为该臂的休息位。

**腕部跟随是关节空间的视觉伺服，不走逆解。** 手在画面里偏左右就转 shoulder_pan，偏上下就转 wrist_flex，其余关节保持初始位。关节转动方向与画面方向的对应关系由运动学在初始位处数值求得；相机安装方向不同用 `cameras.*.rotate` 修正，仍然反了再用 `arms.*.follow_*_sign`。

**跟随用“瞄准”而不是“累加误差”。** 每来一帧新的观测，先把像素误差换算成角度，再加上**拍下这一帧时**手臂实际所在的偏转量，得到“手在哪个方向”这个绝对目标，指令直接朝它去。这样同一帧观测不会被重复计入，检测延迟也被扣掉了。在此之上还有两项：

- 预判：由相邻两帧的目标变化估计手的角速度，按 `follow.lead_s` 向前外推，抵消检测和舵机的延迟。
- 续追：手出画面后的 `follow.coast_s` 内，沿手原来的移动方向继续转并逐渐减速，便于重新找到；之后保持，超过 `follow.lost_timeout_s` 才回初始位。

像素到角度的换算依赖视场角，而视场角是估计值，所以乘了一个略小于 1 的 `follow.aim_scale`，宁可分两帧到位也不过冲。

**腕部跟随时两只臂各跟各的。** 每只臂只看自己的腕部相机，跟自己视野里最优的那只手，不判断两只臂看到的是不是同一只手。选手在相机线程里做（`CameraWorker._update_primary`）：按“检测置信度 × 离画面中心的远近 × 在画面里的大小”给视野里每只手打分，锁定分数最高的；锁定后按画面位置就近延续同一只手，只有另一只手的分数高出 1.5 倍并持续 0.5 秒，或锁定的手消失了，才换。两只臂朝中间转时由中柱避让限位兜底。

**可选的“至多一只在跟”。** 把 `follow.single_tracker` 设为 `true` 后，两只臂同一时刻至多一只在跟：没有跟随臂时把跟随权交给视野评分最高的那只；已有跟随臂时，另一只臂要高出 `follow.switch_margin`（默认 25%）并持续 `follow.switch_hold_s`（默认 0.6 秒）才换；当前跟随臂看不到手时也要等同样长的宽限期才移交。没拿到跟随权的臂回到并停在初始位。

**深度引导默认是“指向式”。** `fused` 模式在腕部跟随的基础上多了一路来自深度相机的引导：深度相机看到手、而没有任何腕部相机看到时，把手的 3D 位置换算到各臂的基座系，算出每只臂要把腕部相机光轴对准它所需的肩部旋转和腕部俯仰偏转量，交给转角最省的那只臂。这个偏转量和腕部相机的观测走同一条瞄准通道（同样有预判、限速和限位），手一进入腕部视野就由腕部相机接管，因为它更准。“至多一只臂在跟”的规则不变。只转动、不伸缩，所以对外参精度要求低：只要能把手带进腕部相机约 90° 的视野即可。

**伸出式引导保留为可选项**（`fused.reach: true`）：把手的位置沿“肩部 → 手”的连线取一点作为夹爪目标，离手保持 `fused.standoff`，腕部相机做小角度精调。它需要更准的外参，并且受手臂重力下垂影响，尚未在真机上验证。

**外参可以自动标定。** 把外参看成一个 PnP 问题：深度相机给出手的 3D 位置，臂上的腕部相机给出同一只手的方向（由关节角和画面坐标换算出的视线）。跟随过程中，只要跟随臂的腕部相机和深度相机同时看到手，就记下一对样本；攒够后做多初值的非线性最小二乘并剔除离群样本。采样有三条限制：两路观测要足够同时；手要在腕部画面中部（视场角是估计值，边缘换算不准）；深度相机画面里恰好只有一只手（否则无法确定是不是同一只）。原来在深度画面上点击夹爪尖的手动方式仍然保留。

**云台固定。** 外参只在标定时的云台姿态下成立。标定时记录云台角，进入深度引导模式会把云台驱动回该角度；云台偏离超过 3° 时深度引导暂停。

**单臂停用。** 每只臂可以单独停用，停用后在任何模式下都只保持当前位置，用于首次上电逐只调试，或演示时只用一只臂。

**安全处理集中在一处。** 所有模式算出的目标都经过 `_tick_arm` 的同一段代码：

1. 急停：目标冻结在当前位置，忽略一切运动输入。
2. 受阻让位：实测与目标偏差超过 `stall_error_deg` 并持续 `stall_hold_s`，放弃目标并暂停 1.5 秒。要求持续一段时间，是因为快速跟随时会有瞬时滞后。
3. 关节限速：每拍目标变化不超过 `max_joint_speed_deg_s`。回初始位和收到休息位另按较慢的 `home_speed_deg_s`。
4. 关节限位：按该臂生效的限位裁剪。

笛卡尔目标另外受工作空间包围盒和两臂中线限制。按键靠心跳维持，超过 `key_timeout_s` 没收到就视为全部松开。

**退出时先收手。** 正常退出会先把两臂收到休息位再释放力矩；急停状态下退出则保持力矩不动。

## 配置

默认值全部在 `backend/soarm/config.py` 的 dataclass 里，`config/config.yaml` 只覆盖与本机有关的项（串口、相机设备、云台刻度、方向符号）。写了不存在的配置项会直接报错。

## 真机验证情况

已在两只臂上验证：连接不跳变、展开到初始位、腕部跟随的方向与回位、中柱避让、退出时自动收手。结果见 [devices/VERIFIED.md](devices/VERIFIED.md)。

尚未验证：

- 深度引导和外参自动标定只在合成数据上测过。真机上的阻塞点是深度相机的朝向，见 [devices/VERIFIED.md](devices/VERIFIED.md)。

- 键盘笛卡尔控制在真机上的各个方向。
- 位置环只有比例项，手臂伸出时有约 2–3 cm 的重力下垂，逆解没有补偿它。
- 腕部相机视场角按 90° 估计，只影响跟随的灵敏度。
