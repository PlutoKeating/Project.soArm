# 前端架构

## 数据流

```text
启动   GET /api/meta ──► buildUi()   按键位表生成键帽，按相机名创建视频 <img>
运行   WebSocket /ws 下行状态 ──► render()   整页按状态重绘，前端不保存业务状态
操作   按钮 / 快捷键 ──► POST /api/...       失败时把后端返回的原因显示在提示条
按键   keydown / keyup ──► pressed 集合 ──► WebSocket 上行 {"keys": [...]}
视频   <img src="/stream/{camera}">          MJPEG，浏览器原生解码
```

界面完全由后端状态驱动：模式、急停、连接状态都以 WebSocket 推来的快照为准，按钮点击后不做乐观更新。键位表也来自后端，前后端不会各写一份。

## 按键安全

运动键“按住才动”，前端负责三件事：

1. **心跳**：每 100 ms 发送一次当前按住的键，按键变化时立即发送。后端 0.35 秒没收到就停。
2. **失焦即松开**：窗口失焦或标签页切到后台时浏览器收不到 `keyup`，所以在 `blur` 和 `visibilitychange` 里主动清空并上报。
3. **空格只用于急停**：按钮点击后立即移除焦点，避免空格触发刚点过的按钮而不是急停。

带 Ctrl / Alt / Meta 的组合键一律忽略，不影响浏览器自身快捷键。

## 标定点击的坐标换算

视频以 `object-fit: contain` 显示，四周可能有黑边。`onHeadClick` 先按图像原始宽高算出实际显示区域，再把点击位置换算成 0–1 的归一化坐标发给后端，点在黑边上的点击被忽略。

## 断线

WebSocket 断开后每秒重连一次，顶栏显示断开状态。断开期间后端因收不到心跳会自动停止运动。
